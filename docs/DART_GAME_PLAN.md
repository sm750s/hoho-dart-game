# 호호가족의 다트 게임 — 기획서

## 1. 프로젝트 목표

AI에게 아이디어를 설명하고, 결과를 직접 플레이하며, 원하는 방향으로 고치는 경험을 한다. 한 번에 완성품을 만들지 않고 **매 Phase마다 실행 가능한 게임**을 남긴다.

- 게임 제목: **호호가족의 다트 게임**
- 대상: 보호자와 아이가 함께 만드는 입문용 프로젝트
- 실행 환경: PC 브라우저, 이후 터치 기기 지원
- 구성: **React + TypeScript를 필수 사용**하고 CSS로 스타일 구현. 백엔드·회원가입·데이터베이스 없음
- 시작 방법: 의존성 설치 후 프런트엔드 개발 서버를 실행하고 브라우저로 접속
- 기본 게임: 한 사람이 다트 3발을 던져 총점을 확인하는 점수 도전
- 범위: 실제 다트의 물리 법칙보다 이해하기 쉬운 조작과 즉각적인 피드백을 우선

## 2. 함께 만드는 진행 방식

각 Phase를 ‘아이디어 정하기 → AI에게 요청하기 → 실행하기 → 관찰하기 → 한 가지 고치기’ 순서로 진행한다. 단계당 20~40분을 출발점으로 삼고, 아이의 흥미에 따라 나눠 진행한다.

아이는 색상·규칙·효과를 선택하고 플레이 결과를 설명한다. 보호자는 파일 저장과 실행을 돕고, AI는 현재 단계에 필요한 코드와 짧은 설명을 제공한다. 다음 단계는 현재 단계의 완료 기준을 확인한 뒤 시작한다.

**AI 요청 공통 문장:** “현재 단계의 기능만 추가해줘. 기존 기능은 유지하고, 변경한 내용과 확인 방법을 쉽게 설명해줘.”

## 3. 단계별 개발 계획

### Phase 1 — 다트판이 화면에 나타나요 [구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

**목표:** 아이가 선택한 색으로 첫 화면을 만든다.

- 제목, 동심원 다트판, 간단한 안내 문구 표시
- React + TypeScript 프로젝트를 구성하고 화면을 React 컴포넌트로 구현
- 다트판은 CSS 또는 SVG로 직접 그려 외부 이미지 없이 실행
- 아직 점수 계산이나 던지기 기능은 추가하지 않음

**아이와 할 활동:** 정해진 게임 제목을 화면에서 확인하고 다트판 색을 골라 바꿔보기.

**완료 기준:** React + TypeScript로 구현한 화면이 개발 서버에서 표시되고, 새로고침해도 정상적으로 표시된다. 타입 검사와 프로덕션 빌드가 통과한다.

**AI 요청 예시:** “React + TypeScript로 다트 게임 첫 화면을 만들어줘. 제목은 ‘호호가족의 다트 게임’이고, 초록색과 갈색 동심원 다트판을 보여줘. 백엔드 없이 프런트엔드만으로 실행되게 해줘.”

### Phase 2 — 클릭하면 점수가 생겨요 [구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

**목표:** 가장 단순한 방법으로 게임을 플레이한다.

- 다트판을 클릭하면 해당 위치에 명중 표시
- 가장 작은 중심점부터 바깥으로 100·90·80·70·60·50·40·30·20·10점, 테두리·판 밖 0점
- 마지막 점수와 누적 점수 표시
- 던지기 횟수 제한 없이 연습하고, 초기화 버튼으로 다시 시작

**영역 기준:** SVG의 중심은 `(200, 200)`이다. 100점 중심점부터 10점 바깥 띠까지 10개 영역을 둔다. 각 영역의 반지름은 중심부터 6·24·43·62·81·100·119·138·157·178이며, 그림과 점수 계산은 `SCORE_ZONES` 정의를 공유한다. 중심점은 작게 유지하고 나머지 띠 폭은 약 18~21로 좁힌다. 어두운 테두리와 판 밖은 0점이며, Phase 2에서는 다트판 주변 점무늬 영역에서도 클릭을 받으며 Phase 4부터 타이밍 조준으로 위치를 정한다. 가장 최근 명중 표시를 노란색으로 강조한다.

**아이와 할 활동:** 중심과 가장자리를 클릭해 점수 차이를 확인하고 점수 규칙을 바꿔보기.

**완료 기준:** 각 영역의 점수가 맞고, 판 밖 클릭은 0점이며, 초기화하면 기록이 사라진다. 영역 경계는 더 안쪽 영역의 점수로 처리한다.

### Phase 3 — 세 발로 도전해요 [구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

**목표:** 시작과 끝이 있는 한 판을 만든다.

- 한 판에 3발, 남은 횟수와 발별 점수 표시
- 세 번째 발 이후 총점과 결과 메시지 표시
- 게임 종료 후 추가 입력은 점수에 반영하지 않음
- ‘다시 하기’ 버튼으로 새 게임 시작

**아이와 할 활동:** 목표 점수를 정하고 결과 메시지를 직접 작성하기.

**현재 기본 설정:** 목표 180점, 만점 300점. `src/game.ts`의 `TARGET_SCORE`와 `getResultMessage`를 수정해 목표와 응원 문구를 바꾼다. 다시 하기는 진행 중에도 사용할 수 있고, 발별 기록·점수·명중 표시를 모두 초기화한다.

**추가 요청 반영:** 각 투척에는 점수별 효과음(0~50점 하강, 60~100점 상승, 높은 점수일수록 더 높은 음), 세 번째 투척 뒤에는 “따단!” 느낌의 완료음을 재생한다. Web Audio로 외부 음원 없이 생성하며 첫 투척 클릭에서 오디오를 활성화한다. 효과음 켜기·끄기를 지원하고, 음소거·다시 하기·화면 종료 시 재생과 예약을 취소한다. 소리를 사용할 수 없어도 게임은 동작한다. 먼저 구현한 소리 제어는 현재 Phase 5에 통합되어 있다.

**완료 기준:** 판 밖으로 던져도 한 발이 소모되고, 정확히 3발 뒤 종료되며, 다시 하기가 모든 게임 상태를 초기화한다.

### Phase 4 — 타이밍에 맞춰 던져요 [구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

**목표:** 원하는 위치를 바로 클릭하는 방식에서 타이밍 게임으로 발전한다.

- 조준점이 다트판 주변을 좌우로 움직이고, 버튼을 누르면 가로 위치 확정
- 이어서 위아래로 움직이고, 다시 누르면 세로 위치 확정 후 투척
- 버튼 클릭 또는 Space 키로 조작
- 짧은 다트 이동 애니메이션과 명중 효과 추가
- 쉬움·보통·빠름·매우 빠름 난이도는 조준점 이동 속도로 조절

**아이와 할 활동:** 느린 속도와 빠른 속도를 비교하고 적당한 난이도를 고르기.

**현재 구현:** 쉬움 150, 보통 270, 빠름 420, 매우 빠름 600 SVG 좌표 단위/초로 움직인다. 위치 확정은 버튼 또는 Space로 조작하고 직접 클릭 투척은 사용하지 않는다. 약 0.45초 비행 후 점수를 반영한다. 비행 중 난이도 변경을 막고 다시 하기는 조준·비행·예약된 소리를 취소한다. Space 자동 반복은 무시하며 버튼·선택 항목에 포커스가 있으면 해당 요소의 기본 키보드 동작을 따른다.

**완료 기준:** 두 번의 조작으로 한 발이 결정되고, 애니메이션 중 연속 입력해도 중복 투척되지 않는다. 다시 하기는 진행 중인 조준과 애니메이션도 취소한다.

### Phase 5 — 우리만의 게임으로 꾸며요 [구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

**목표:** 아이의 취향을 반영해 완성도를 높인다.

- 기기 화면에 맞춰 크기 조절, 터치 버튼 지원
- 최고 점수를 브라우저의 `localStorage`에 저장
- 소리 켜기·끄기, 결과에 따른 축하 효과 추가
- 초기화 버튼과 최고 기록 삭제 버튼을 구분

**아이와 할 활동:** 테마, 축하 문구, 효과를 선택하고 가족에게 게임을 소개하기.

**현재 구현:** 완료한 판만 최고 기록으로 저장하며 모든 난이도가 기록 하나를 공유한다. 다시 하기는 최고 기록을 유지하고 기록 삭제는 현재 판을 유지한다. 삭제한 판은 다시 저장하지 않으며 다음 완료한 판부터 갱신한다. 저장 차단·용량 초과·잘못된 기록을 처리하고, 저장 실패 시 화면 안의 기록을 유지하며 상태를 안내한다. 저장 키는 `family-dart-best-score-v1-100`이다. 만점·새 기록·목표 달성은 색종이와 축하 문구, 그 외는 응원 문구를 표시한다. 버튼은 최소 44px로 터치에 대응하고 동작 줄이기 설정에서는 색종이를 생략한다.

**완료 기준:** 작은 화면에서도 버튼을 누를 수 있고, 같은 브라우저에서 다시 열었을 때 최고 기록이 유지된다. 저장 기능을 사용할 수 없는 환경에서도 게임은 실행된다.

### Phase 6 — 미션과 가족 놀이 [6-1~6-4 구현 완료 · 핵심 브라우저 검증 통과 · 추가 확인 남음]

네 가지 확장 아이디어를 한 단계씩 개발한다. 상세 규칙과 완료 기준은 [Phase 6 계획](PHASE_6_PLAN.md)을 따른다. ‘Phase 6 진행’ 요청은 미구현인 가장 이른 하위 단계 하나만 구현하며 각 하위 단계 결과를 확인한 뒤 후속 요청으로 다음 단계를 진행한다.

| 순서 | 기능 | 플레이 결과 |
| --- | --- | --- |
| 6-1 | 미션 도전 | 성공 판 별 1개·중복 방지·새로고침 복원·실패/중도 재시작 미지급 통과. 네 미션 전체 선택 흐름은 미확인. (2026-10-10, Chrome CDP; 상세 보고서 참고) |
| 6-2 | 가족 대결 | 설정/차례 대기 Space 차단·개인별 쉬움/보통·각자 3발·명시적 넘기기·승패/동점·비행 중 재시작 통과. 실제 기기·청취는 미확인. (2026-10-10, Chrome CDP; 상세 보고서 참고) |
| 6-3 | 보물 모으기 | 2→3/4→5/7→8 해제·우주/별빛 선택 복원·초기화 취소/확인·최고 기록 보존 통과. (2026-10-10, Chrome CDP; 상세 보고서 참고) |
| 6-4 | 행운의 점수 | 영역 강조·판 내 고정·반복 명중 배지 하나·점수/별 분리·재추첨·동작 줄이기·음소거 UI 통과. 실제 청취는 미확인. (2026-10-10, Chrome CDP; 상세 보고서 참고) |

기본 모드와 기존 3발·최대 300점·목표 180점 규칙을 유지한다. 별과 배지는 점수와 분리하고 모든 기능은 브라우저에서 실행한다. 6-1~6-4를 모두 구현했다. 사용자 요청으로 남은 보물 모으기와 행운의 점수를 함께 완료했다. 핵심 브라우저 자동화는 통과했으며 실제 기기·효과음 청취 등은 남아 있다.

## 4. 화면과 규칙

화면은 위에서부터 게임 제목, 총점·남은 횟수, 다트판, 조작 안내·버튼, 발별 기록 순서로 배치한다. 결과는 화면 안에 표시하고 색상뿐 아니라 숫자와 글자로도 전달한다.

Phase 2의 간단한 동심원 점수 규칙을 이후에도 유지한다. 실제 다트의 20개 숫자 구역, 더블·트리플, 301점 규칙은 기본 과정이 끝난 뒤 선택 과제로 남긴다.

## 5. 기술 구성과 파일

```text
index.html                  # React 앱을 연결하는 HTML 진입점
package.json                # 의존성과 개발·검증·빌드 명령
tsconfig.json               # TypeScript 설정
vite.config.ts              # 프런트엔드 개발·빌드 설정
src/main.tsx                # React 앱 시작
src/App.tsx                 # 전체 화면 구성
src/components/DartBoard.tsx # 다트판 컴포넌트
src/style.css               # 색상, 배치, 효과
src/game.ts                 # 점수, 좌표 변환, 3발 게임 상태, 결과 문구
src/aim.ts                  # 조준·비행 상태와 난이도별 이동 규칙
src/useTimingAim.ts         # 프레임, 버튼·키보드 입력, 재시작
src/treasures.ts            # 보물 해제와 선택 검증
src/luck.ts                 # 행운 점수 추첨과 명중 판정
src/components/TreasurePanel.tsx # 보물 선택·초기화 확인
tests/expansion.test.ts     # 보물과 행운 테스트
src/family.ts               # 두 사람의 설정·차례·대결 결과
src/components/FamilyPanel.tsx # 가족 대결 화면
src/missions.ts             # 미션 판정과 별 지급
tests/family.test.ts        # 대결 차례·승패·재시작 테스트
src/storage.ts              # 최고 기록 저장·복원·삭제
src/components/Celebration.tsx # 결과별 축하 효과
src/sound.ts                # 투척·완료 효과음과 재생 취소
tests/game.test.ts          # 게임 로직 테스트
tests/aim.test.ts           # 두 단계 조준·비행 테스트
tests/storage.test.ts       # 기록 저장과 실패 처리 테스트
tests/sound.test.ts         # 오디오 제어 테스트
```

UI는 React 함수 컴포넌트와 TypeScript(`.tsx`, `.ts`)로 구현하며, Vite를 개발·빌드 도구로 사용한다. 게임 상태와 입력·점수 처리는 모두 브라우저에서 실행한다. 별도 백엔드나 외부 API에 의존하지 않는다. 화면 크기가 달라져도 점수가 같도록 클릭 좌표를 다트판 기준 좌표로 변환한다.

Node.js 22.12 이상에서 `npm install`, `npm run dev`, `npm run typecheck`, `npm run build`, `npm run preview` 명령을 사용한다. 개발 서버와 빌드 미리보기는 프런트엔드 파일 제공용이며 게임용 백엔드가 아니다. 빌드 결과는 정적 호스팅으로 제공할 수 있다. `index.html`을 직접 여는 방식은 실행 요건에서 제외한다.

현재 Phase 1~6 전체가 React + TypeScript로 구현되어 있다. `src/App.tsx`에서 화면과 게임 상태를 관리하고 `src/components/DartBoard.tsx`에서 다트판과 명중 표시를 보여준다. Phase 2의 무제한 연습은 Phase 3의 3발 도전으로, 직접 클릭 투척은 Phase 4의 타이밍 조작으로 발전시켰다. `src/game.ts`의 로직은 `npm test`로 검증한다. `src/style.css`의 색상 변수를 바꾸는 활동을 유지하며, 이후 단계는 이 구조를 기반으로 진행한다.

### 2026-10-10 홈·게임·결과 화면 분리

후속 사용자 확인: 모바일 효과음 재생 정상. 초기 무음은 소리를 꺼둔 상태였으며 오디오 코드 수정은 하지 않았다. 구체적인 기기/브라우저 및 세부 음색·취소 동작은 미확인이다.

사용자 요청으로 세 단계 화면을 구현했다. 홈에서 모드·미션·속도·가족 이름을 고르고 ‘게임 시작’을 누른다. 단독 모드는 세 발 종료, 가족은 두 사람 모두 종료 시 결과로 이동한다. 첫 사람 종료는 명시적 차례 대기다. 결과는 점수·발별 기록·승패·별·배지를 요약한다. ‘다시 하기’는 가족도 같은 설정으로 즉시 시작하고, ‘홈으로’는 비행·소리를 취소하고 설정으로 돌아간다. 새로고침은 홈으로 돌아간다. 꾸미기·별 초기화는 홈에서만 제공하며 초기화 후 시작을 기다린다. 이전 한 화면 설정 및 대결 재시작의 설정 복귀 설명은 이 변경으로 대체한다.
